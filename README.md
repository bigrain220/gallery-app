# Collector's Room 02 预约小程序

原生微信小程序，通过 `wx.cloud.callContainer` 访问微信云托管 TF 服务。活动信息、日历状态、时段、预约创建、详情、列表及取消均来自后端接口。

## 云托管配置

配置集中在 `config/services.js`：

| 配置 | 当前值 |
|---|---|
| 环境 | `prod-d3giey1bt59348a38` |
| 服务名 | `tf` |
| 租户 | `1` |
| 接口前缀 | `/app-api` |
| 单次请求超时 | 15 秒 |

`app.js` 调用 `wx.cloud.init()` 初始化小程序的云托管调用能力；环境 ID 通过每次 `callContainer.config.env` 指定。所有请求统一携带 `X-WX-SERVICE: tf`、`tenant-id: 1`，GET 参数编码到查询字符串，POST 请求使用 JSON。

在微信开发者工具中导入本目录并使用项目配置中的真实 AppID。确认目标云托管服务已部署、允许该小程序访问，并能处理 `/app-api/tf/*` 路径。项目无需 npm 构建。

## 页面与接口

首次进入首页时，品牌加载图作为独立遮罩，从图片加载完成后起至少展示 1.2 秒。无预约时同时等待当前首页主图的加载事件；有预约时直接在同一入口页的遮罩下准备预约列表，全程保留同一个加载图，不执行页面跳转或重新计时；至少展示 1.2 秒且列表数据准备好后，再用 180 毫秒淡出。淡出计时从样式更新的渲染回调起算，避免渲染较慢时提前移除遮罩。图片回调缺失有超时兜底，加载错误不阻断进入；退到后台或卸载页面时取消动画计时。

四个页面共用常驻的 loading 模板，图片节点不随遮罩开关销毁。小程序 `App.onHide` 时提前给当前可见页面盖上 loading，减少 Android 热启动时先恢复旧页面、再切换 loading 的闪屏；`Page.onHide` 只取消计时和过期请求，普通日期、时间和详情页跳转不会重播 loading。回前台后从本次可见时间重新计算至少 1.2 秒的展示时长，等待当前页面的身份、列表、详情或日期时段复查结束再淡出；后台停留时间不计入展示时长，后台返回的请求与过期动画不能移除遮罩。表单和选择草稿继续保留。微信原生恢复动画可能使用早于业务代码更新的缓存画面，这部分仍需在出现问题的 Android 真机上验证。

项目使用微信原生导航栏：`pages/index/index` 保留活动与表单，日期、时间分别位于 `pages/date/date`、`pages/time/time`，预约列表也由首页同页展示，黑白详情位于 `pages/reservation/reservation`。子页面通过 `wx.navigateTo` 入栈，使用微信自带返回箭头和手势返回。日期及时间仅在确认后通过 EventChannel 回传，直接返回不改变原选择；选择日期和时间期间保留原表单，姓名、手机号、隐私勾选及滚动位置不会丢失。两个选择页的确认按钮固定在底部并预留安全区。缺少来源上下文的子页面回到首页的预约状态查询入口。

日期页的标题、状态说明与星期栏位于滚动区外，星期始终固定在顶部；月份和日期在中间独立滚动，七列与星期栏对齐，底部确认按钮保持固定。

存在有效预约时，入口页切换为“我的预约”视图，活动表单保持挂载但隐藏，不通过 `wx.reLaunch`、`wx.redirectTo` 或 `wx.navigateTo` 切换列表页面。列表与表单共用 `pages/index/index`，唯一的启动遮罩持续覆盖到目标内容就绪。无有效预约时展示表单；主动查看历史记录也在同页展示列表，并提供“返回预约”入口，返回后保留表单草稿与原滚动位置。

新预约成功后直接使用 `wx.navigateTo` 打开设计提供的黑白预约详情页，首帧即显示本次已确认的预约，不先进入“我的预约”列表，不等待列表接口或详情图片，也不重播开场。详情图片在后台缓存，打开详情时通过一次性上下文预填，再通过 EventChannel 正常初始化并刷新预约详情；详情接口失败仍保留预约成功状态并提供刷新入口。详情入栈后，隐藏的入口页提前渲染为包含本次已确认预约的列表，首次返回动画直接露出该列表，再同步完整记录；同步期间、列表未及时返回新记录或查询失败时均保留本次预约，不先显示表单或全屏 loading。详情打开期间若发生过小程序后台切前台，返回时仍按微信身份复查，有效预约已取消则恢复表单。仅在原生详情页面打开失败时回退到列表，保留已确认预约并提供“查看详情”重试入口。

取消预约成功或前台复查发现已无有效预约时，入口页直接恢复空白表单，不销毁或重建页面；取消失败保留列表和确认弹框。默认首页原生导航栏不带返回箭头，详情页保留返回列表的箭头。取消弹框的两个按钮继续使用等宽布局与边框盒尺寸。

启动时先显示加载页并通过微信身份查询预约状态：有有效预约直接进入“我的预约”，无有效预约才显示原活动首页和填写表单，移除首页预约卡片。查询失败或入口页面打开失败显示重新加载入口，期间不展示表单。活动信息已加载成功时，重新加载只重查预约状态；活动加载失败时才重试完整初始化。已取消、已核销、已过期的记录不阻挡重新预约。预约根列表从后台回到前台时按微信身份复查状态，其他设备取消后可恢复首页；普通从详情返回时保留原列表和滚动位置，不再次查询，详情查询到的变化通过 EventChannel 仅更新对应记录。若详情打开期间小程序回过前台，或打开详情打断了尚未完成的列表查询，返回时仍执行必要复查；从日期、时段或无有效预约的预约列表返回表单时，直接恢复已挂载的表单与滚动位置，不重复查询或切换全屏加载页。在列表查询中首次发现有效预约时，将同页列表标记为有效预约入口，不再提供返回表单的按钮。

各页面入口使用顶层静态 `require` 引入 `services/booking-page.js`。开发时关闭 `ignoreDevUnusedFiles`，避免动态跳转所需的脚本和页面模板被过滤；`tmp`、测试和原始素材仍通过打包忽略清单排除。修改页面清单或入口模块后需在微信开发者工具中完整编译，并实际打开各页面验证，Node 测试和单文件编译不能替代整包启动验证。

| 页面/动作 | 接口 |
|---|---|
| 活动展示 | `GET /app-api/tf/activity/get` |
| 启动时查询当前微信有效预约 | `GET /app-api/tf/booking/get-by-openid` |
| 日期选择 | `GET /app-api/tf/booking/month-status?month=yyyy-MM` |
| 时段选择与提交前复查 | `GET /app-api/tf/booking/slot-list?date=yyyy-MM-dd` |
| 提交 | `POST /app-api/tf/booking/create` |
| 预约详情刷新 | `GET /app-api/tf/booking/get?id=...&phone=...` |
| 我的预约（进入时自动加载） | `GET /app-api/tf/booking/list-by-phone?phone=...` |
| 取消 | `POST /app-api/tf/booking/cancel` |

请求层处理 HTTP 错误、网络错误及 `{ code, data, msg }` 业务错误。日期、时间及创建时间兼容 Java 数组序列化和字符串。日历范围来自活动起止日期，只允许选择后端状态为 `0` 的日期或时段；未返回的日期默认不可选。切换日期会清除原时段。

提交使用后端时段 `id` 作为 `slotId`。提交按钮防重入；创建成功后即记录后端返回的预约 ID，直接进入预约详情；详情加载失败时保留本次已确认预约并提供刷新入口。创建请求失败时会查询有效预约或手机号列表，确认是否实际已创建，恢复成功同样直接进入预约详情。取消请求使用预约记录自身的 ID 和手机号，后端确认成功后才清理当前预约状态。

预约成功后立即清空姓名、手机号、日期、时段及选择草稿，并取消隐私勾选、重置表单滚动位置。创建超时但后端确认预约已存在时同样清空；提交失败且未确认成功时保留内容以便重试。用户主动打开的详情页直接读取预约详情，详情刷新和查看历史记录不会回填表单。已保存资料仅用于自动查询预约，重新打开小程序也不自动填入表单。

活动标题图、封面、现场图、成功页背景、地址、时间、联系方式及隐私说明绑定活动接口。后端未配置图片时使用现有本地素材；标题图缺省时使用设计提供的三行字标。主图、标题、开放时间和表单按 Figma 的 375px 画板比例排布，首页不额外展示活动介绍、预约须知及联系信息区。手机号按接口文档手动输入。

首页隐私说明和下划线链接按 Figma 展示。点击“隐私政策”后，通过可滚动弹窗展示后台 `privacyPolicy` 配置，兼容富文本 HTML 和多行纯文本；关闭弹窗不会改变勾选状态。后台未配置时在弹窗内提示，不跳转微信隐私指引。

隐私说明区域支持点击文字、方框或区域内留白切换勾选。勾选框与政策链接使用独立按钮并阻止点击冒泡，避免方框一次点击切换两次；点击“隐私政策”仅打开弹窗。时段按钮固定铺满网格列，设置上下与左右留白，禁用状态显式使用浅灰背景，时间与状态文字之间保留间距。

点击隐私说明文字或勾选框可以选中或取消同意，查看或关闭政策弹窗不会改变勾选状态。未勾选时提交按钮置灰禁用，提交方法也会在已有预约跳转及任何请求前检查明确同意。提交过程中锁定勾选状态，避免等待时段复查期间撤销勾选后仍发出创建请求。

成功页按 Figma `13:913` 排布三行标题、预约时间、地址、状态及“更多信息”。联系方式以纯文字展示，固定标签为 `WECHAT:`、`REDBOOK:`、`EMAIL:`；标签采用等宽列并右对齐，使冒号处于同一竖线，右侧内容左对齐，每项联系方式保持单行，内容列不压缩或拆行，整体按内容宽度居中。分别读取接口 `wechat`、`redbook`、`email` 的实际值，不转换大小写；空值、缺失或纯空白的项目不展示，全部为空时隐藏“更多信息”。三项联系方式没有点击、复制、跳转或名片弹窗。取消入口保留在“我的预约”中。小屏可滚动查看完整成功页。加载页使用原有 `assets/loading.png`，以 `aspectFill` 铺满导航栏下方区域。

“我的预约”采用浅灰白底与黑白预约卡片，突出日期、时段及预约状态；移除页内返回/关闭控制区、手机号输入和查询按钮，使用微信原生导航，有效预约的列表作为根页面时没有返回首页箭头。有效预约卡片在操作按钮上方展示重新预约说明，明确取消成功后会自动返回预约页面，并加强现有“重新/取消预约”按钮的文字与边框对比度；已取消、已核销及过期记录不展示该提示。查询成功且没有有效预约时，底部固定显示独立的黑色“去预约”按钮，以轻微圆角、阴影与顶部短渐变区分列表内容，点击后恢复现有预约表单；查询中、查询失败或有有效预约时隐藏该入口。列表可滚动到按钮区域下方，内容底部为按钮、留白与手机安全区预留空间，滚到底时最后一条记录仍可完整查看；按钮外围的渐变区域不拦截列表触摸。进入时优先使用当前有效预约、本机预约引用或已保存资料的手机号自动加载，最后使用表单中填写的有效手机号；没有可用手机号时尝试微信身份查询。页面提供加载、空记录和失败重试状态，详情与取消仍使用原有接口。

## 地址地图

成功页和活动说明中的地址可点击，通过 `wx.openLocation` 打开微信内置地图查看场馆，并使用地图提供的路线与导航入口。地图打开失败时可选择复制完整地址；主动取消打开地图时不提示错误。此入口不调用 `wx.getLocation` 获取访客位置，也无需配置地图服务 Key。

当前文安路30号的楼宇坐标集中在 `config/venue.js`，采用 GCJ-02 坐标系，楼层与房间号保留在地图地址说明中。坐标来自[百度地图门牌导航点](https://map.baidu.com/mobile/webapp/place/detail/qt=s&wd=上海文安路30号&c=289/vt=map)，由 BD09MC 转为 GCJ-02。后续活动接口如返回有效的 `latitude`、`longitude`（数值或数值字符串，GCJ-02），优先使用接口坐标。现有接口清单未定义这两个字段；若更换到其他地址，需要同步配置对应坐标，缺少坐标时提供复制地址入口，避免导航到原场馆。

API 参考：[微信内置地图](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.openLocation.html)。上线前需在微信真机上检查地图打开与路线入口。

## 微信身份与接口约定

微信云托管会把调用人的微信身份注入**后端请求头** `X-WX-OPENID`；客户端不伪造该头，不使用云函数，也不在小程序中保存 AppSecret。

当前对接约定：前端无参调用 `GET /app-api/tf/booking/get-by-openid`，由后端从可信云托管请求头读取 `X-WX-OPENID`，不再要求前端传入 `openid` 查询参数。原始资料 `移动端接口清单.md` 中的 `uni.login` / `code2session` 流程和必填查询参数描述由本节约定替代；后端需按此约定配合部署，前端不新增登录或换取身份的接口。

接口仍使用 `{ code, data, msg }` 响应结构：成功时 `code = 0`，`data` 返回有效预约对象或明确的 `null`。前端仅在收到正常的无有效预约结果后展示表单；缺少身份、HTTP / 业务错误以及格式异常都显示重试，不能按无预约处理。启动判断和预约根列表复查均只依赖身份查询，不再使用本机预约 ID、已保存手机号或表单手机号回查，也不再忽略缺少 `openid` 的 400 错误。

创建请求仅发送 `name`、`phone`、`date`、`slotId`，由后端读取同一身份头并写入 `openid`，校验手机号和微信号的有效预约唯一性。详情、列表及取消请求继续携带现有接口要求的预约 ID 或手机号，归属由后端结合当前微信身份校验。

本机仍保存已确认预约的姓名、手机号及预约引用 `{ id, phone }`，用于“我的预约”的手机号列表查询，不回填预约表单，也不参与启动时的预约状态判断。提交结果未知时仍可按本次提交手机号确认是否已创建。本机缓存按环境和租户隔离。查看已取消或已核销记录不会覆盖其他有效预约引用。

- [通过 SDK 自动携带身份及后端请求头](https://docs.cloudbase.net/faq/knowledge/cloudrun-authentication-integration)
