# Collector’s Room Vol.2 预约小程序

原生微信小程序 + 微信云开发实现，页面按 `TF小程序` 中的需求稿、线框图和原始素材还原。用户身份、手机号保存、预约状态判断、提交预约和取消预约均由云函数完成，客户端不直接读写云数据库。

## 已实现的云端流程

1. 用户打开小程序后调用 `reservation` 云函数，云函数通过上下文中的 OpenID 自动识别用户。
2. 首次访问创建用户档案；再次访问会回显上次保存的姓名和手机号。
3. 若存在有效预约，打开后直接显示预约成功页。
4. 用户点击“微信授权”后，微信会同时完成官方隐私授权与手机号授权；客户端只把一次性动态 `code` 交给云函数，由云函数调用微信接口换取手机号并保存。
5. 提交时云函数再次校验姓名、手机号、日期和可预约时段，并用 OpenID 作为当前预约文档 ID，保证每个用户最多只有一条有效预约。
6. 取消后预约会标记为 `cancelled`，不会从数据库直接删除；用户档案中的姓名和手机号会保留以便下次回显。

## 首次部署

1. 用微信开发者工具导入本目录，并确认右上角选择的是已经配置好的云开发环境。
2. 在开发者工具中右键 `cloudfunctions/reservation`，选择“上传并部署：云端安装依赖”。首次调用时云函数会自动创建 `appointment_users`、`reservations` 两个集合。
3. 自动创建后建议在云开发控制台确认两个集合的权限为“仅管理员可读写”。所有业务访问均经过云函数，不需要开放客户端数据库权限。
4. 如果项目没有设置默认云环境，请把环境 ID 填入 `app.js` 的 `globalData.cloudEnvId`；已设置默认环境则保持空字符串即可。
5. 在微信公众平台完成《小程序用户隐私保护指引》，声明会处理姓名和手机号，并确保小程序主体符合“手机号快速验证组件”的使用条件。
6. 使用真机或体验版测试手机号授权。开发者工具模拟器无法返回真实手机号。

`cloudfunctions/reservation/config.json` 已声明 `phonenumber.getPhoneNumber` 云调用权限。若部署时控制台提示没有该接口权限，请先确认小程序已经完成主体认证，并在云开发控制台为该云函数开通对应微信开放接口权限。

## 数据结构

`appointment_users` 使用 OpenID 作为文档 ID，保存最近一次填写的姓名、手机号、手机号是否来自微信授权以及访问时间。

`reservations` 同样使用 OpenID 作为文档 ID，保存预约姓名、手机号、日期、时段、状态、创建时间、更新时间和取消时间。取消预约只变更状态；再次预约时会复用该用户的当前预约文档。
